1. RATE LIMITING
================================================================================

  Infrastruktur:
    Cloudflare sitter framför Ratsit (cf-ray, cf-cache-status: DYNAMIC).
    Biluppgifter.se använder också Cloudflare.

  Testresultat (20 sökningar utan fördröjning, headless Chromium):
    - 20/20 HTTP 200 med korrekta resultat
    - Svarstid: 1.3–4.2s per sökning
    - Inga blockeringar, CAPTCHAs eller rate-limit-headers
    - Inga X-RateLimit-*, Retry-After eller liknande headers

  Slutsats:
    Vid normal användning sker ingen rate-limiting. Cloudflare kan
    potentiellt blockera vid hundratals snabba anrop men triggas inte
    vid de volymer vi testat (~20-30 anrop i följd).

4. BEGRÄNSNINGAR UTAN INLOGGNING
================================================================================

  Ratsit:
    - Sökfältet ignorerar de sista 4 siffrorna i personnumret
    - Max 3 sidor (30 resultat) utan inloggning
    - Löneuppgifter kräver betalning
    - Kreditupplysning kräver BankID

  Biluppgifter.se:
    - Inga begränsningar för grundläggande ägarinfo
    - Server-side rendered — fungerar i headless utan problem


5. NYCKELFYND: PERSONNUMMER VIA BILUPPGIFTER
================================================================================

  Ratsit maskerar personnumret som "19860528-XXXX" men det fullständiga
  numret finns tillgängligt via TVÅ vägar:

  ─── Väg 1: Direkt uppslag (lookup.js, steg 1) ───

    base64("198605280299") = "MTk4NjA1MjgwMjk5"

    URL: https://biluppgifter.se/brukare/MTk4NjA1MjgwMjk5

    Biluppgifter.se renderar personens namn direkt (server-side, htmx).
    Ingen JavaScript behöver köras — allt finns i HTML vid domcontentloaded.

    Svar: "Emelie Lundqvist, en privatperson som är 39 år..."
    Länk: "Visa Emelie Lundqvist på Ratsit"

  ─── Väg 2: Omvänt via Ratsit-profilsidor (scraper.js) ───

    Varje profilsida på Ratsit laddar:
      GET https://www.ratsit.se/person/biluppgifter/{person-hash}

    Svaret innehåller:
      { "subjectUri": "https://biluppgifter.se/brukare/MTk4NjA1MjgwMjk5" }

    base64-avkodning → 198605280299 → 19860528-0299

  Verifierat med 9+ personer. Fungerar för alla som inte har
  sekretessmarkering (skyddade uppgifter).


6. INTERNT SÖK-API (POST /api/search/combined)
================================================================================

  Ratsits frontend anropar:

    POST https://www.ratsit.se/api/search/combined
    Content-Type: application/json

    {
      "who": "Jakob Eberg 19860528-0299",
      "age": ["16", "120"],
      "phoneticSearch": true,
      "page": 1
    }

  Svaret per person:
    id, firstName, lastName, givenName, age, streetAddress, city,
    gender, married, hasCorporateEngagements, coordinates {lat, lng},
    personUrl, loneKollenUrl, kreditupplysningUrl

  API:et kan inte anropas direkt (kräver session/cookies via webbsidan).
  Playwright interceptar svaret genom att lyssna på response-events.


7. PROFIL-URL FORMAT
================================================================================

  /YYYYMMDD-Förnamn_Efternamn_Stad/{person-hash}

  Exempel:
    /19860528-Jakob_Olof_Eberg_Stockholm/r6jMQAfk9Cx7iDlJMJSJnZ7e6VLAMFIGhmGw0kxf59E

  Samma hash används för biluppgifter-API, lönekollen och kreditupplysning.
  URL:en innehåller INTE de sista 4 siffrorna i personnumret.


8. LOOKUP-FLÖDE (personnummer → fullständig personinfo)
================================================================================

  Steg 1: base64(personnummer) → biluppgifter.se/brukare/{b64}
          Extrahera namn från server-renderad HTML (~1s, headless OK)

  Steg 2: "Namn + Personnummer" → Ratsit sök-API
          Ger vanligtvis exakt 1 träff med fullständig info (~2s)

  Steg 3: (fallback) Om steg 1 missar namn:
          Använd könsfilter (från siffra 11 i personnumret) +
          iterera kandidater via biluppgifter-API:et på profilsidorna

  Total tid: ~3-6 sekunder för identifiering
  Träffsäkerhet: ~99% (missar bara sekretessmarkerade personer)
